Design system

Archived 6 November 2026 · works offline

Simulacrum is the design system for Secretary, a personal assistant server. It's a dark, stripped-back tactical HUD where colour only appears when it means something. It takes its feel from mech-game interfaces and uses no assets from any game.

Leanings

Simulacrum is the overall style. It comes in two leanings, which set the accent and the tint of everything around it:

  • Ayre is the default: an icy blue accent over cool-tinted neutrals.
  • Pyre is the warm leaning: a gold accent over warm-tinted neutrals, with hot shifted redder and darker so the two stay distinct.

Each leaning tints its whites, blacks and greys toward its accent, keeping the same lightness so contrast holds. The item colours steel, moss, amber, rust and plum stay the same in both, because people choose them. Type, spacing and every component are shared. Set the leaning on the root element with data-theme="ayre" or data-theme="pyre".

Content fundamentals

  • Write plainly, in short sentences. Tell the owner what happened and what to do: "Nothing goes out until you approve it."
  • Address the owner as "you". The assistant never says "I".
  • Use sentence case in source text. Labels become uppercase through styling, so write "Approve and send", not "APPROVE AND SEND".
  • Name the system's real concepts exactly: source, sink, cast, router, planner, panel.
  • Write dates as "Thursday 5 November" and times in 24-hour form, "09:30".
  • Use the middle dot to join short facts: "Due Friday · 15 min".
  • Mark missing rules as a visible placeholder such as [YOUR RULE].
  • Use no emoji.

Visual foundations

Colour. Stay neutral by default. Use bg for the screen, panel for containers and raise for anything lifted or selected. Set text in ink, soft and dim, in that order of importance.

Two signals carry all the meaning. Use accent only for model calls and casts. Use hot only for what needs the owner: approvals, refused edges, the now line and today's date. Never use either as decoration.

Selection. Selection is a raised row with a pale line on its outer edge, never a bright fill. Use selected-vertical in vertical lists and selected-horizontal in horizontal selects, with the line covering the container's border. White fills are reserved for the single strongest neutral action.

Item colours. People may colour calendar items with steel, moss, amber, rust, plum or slate. Keep these dark, with ink text. Fitted tasks default to slate.

Type. Set headings, navigation and controls in Saira Semi Condensed, uppercase and tracked: screen-title, brand, nav-label, control-label. Set anything people read in Source Sans 3: body, item-title, meta. Set times, labels and ports in JetBrains Mono: time, readout, label, port.

Shape. Keep every corner square (radius-none). Solid buttons take a chamfer on the top-right corner. Use no shadows except the two selection edges.

Panels. Every window takes corner brackets, top-left and bottom-right, using .sim-panel. Inner boxes, banners and graph nodes do not.

Rulers. Follow each screen heading with .sim-ruler. It is the only decorative line in the system.

Layout. Fix the sidebar at 196px and let content fill the rest. Keep the top-right of the screen header for modal selects, and put actions that belong to one panel inside that panel. Keep every control at least control-height tall.

Focus. Show a solid 2px accent outline on keyboard focus.

Motion. Keep motion subtle, and respect the reduced-motion setting. Animated data pulses along graph edges are planned but not yet in the system.

Backgrounds. Screens are a flat bg. A faint 48px grid, using a line just lighter than bg, is parked as a possible later option.

Iconography

The product has no logo, so set its name in plain type using brand. The sidebar uses two-digit mono numbers in place of icons. Draw small functional glyphs, such as chevrons, as inline square-capped strokes in currentColor. Use no emoji.

Graphs

Build every graph, routing or boundaries, from .sim-node. Sinks are hollow squares on the left and sources are filled squares on the right, each with a mono name. Run edges port to port in arrow. Mark nodes that call the model, and casts, with .sim-node--accent. Draw a refused edge as a dashed hot line.

Components

Layout

Label

A small mono section label with a square marker.

Use .sim-label on a heading inside a panel. Add .sim-label--accent when the section holds model output. The consumer provides the text, in sentence case. Don't use it for field captions, which are plain lowercase mono in dim.

Panel

The window for every grouped surface, marked with corner brackets top-left and bottom-right.

Use .sim-panel for side and detail panels. Add .sim-panel--main for a main surface that holds its own rows or a graph: it takes the stronger line border and a 3px inset that keeps brackets clear of selected rows.

The consumer provides the content and the panel's width. Don't add brackets to banners, inner boxes or graph nodes.

Ruler

A tick-mark separator that closes every screen heading.

Use .sim-ruler with aria-hidden="true" as the last element in the screen header, spanning its full width. The consumer provides the width. Don't use it between content sections, where hair dividers belong.

Navigation

NavItem

A numbered sidebar link, with selection shown as a raised row and a pale left edge.

Use .sim-nav-item links inside a .sim-nav wrapper, each with a two-digit number in a span. Mark the current screen with aria-current="page".

The consumer provides the links, numbers and labels. Keep the numbers in the sidebar's fixed order. Don't use a bright fill for selection.

Toggle

A horizontal modal select, with selection shown as a raised item and a pale line along the bottom edge.

Use .sim-toggle around links or buttons. Mark the choice with aria-current on links or aria-pressed="true" on buttons. The selected item's line covers the container's border, forming its outer edge.

Place toggles in the top-right of the screen header. That space is reserved for modal selects. The consumer provides two to four short options.

Actions

Button

Actions, in three strengths: outlined by default, solid neutral for the main safe action, solid hot when the owner's approval is needed.

Use .sim-btn for most actions. Add .sim-btn--neutral for the single main action in a panel, such as Keep. Add .sim-btn--hot only for an approval, such as Approve and send, and at most once per view.

Solid buttons take a chamfered top-right corner. The consumer provides a short verb-first label in sentence case.

Feedback

Banner

A full-width status strip for a state that affects the whole screen.

Use .sim-banner for a neutral state. Add .sim-banner--hot when something was refused or needs the owner. The consumer provides a short mono title, an optional sentence in a p, and at most one action. Banners take no corner brackets.

Data

CalendarItem

A calendar entry, which people can colour themselves.

Use .sim-cal-block for a fitted task, which defaults to slate. Add --event for events, --ok for a task that needs approval, and --due for an all-day deadline. To apply an item colour, set background to steel, moss, amber, rust, plum or slate.

The hot border on --ok stays on top of any item colour. Offer colours with .sim-swatch buttons in a .sim-swatches row, using .sim-swatch--default for the default and aria-pressed for the current choice. The consumer positions blocks and sets their height. Keep the minimum height at 24px.

ItemRow

A row in a vertical list of items, with selection shown as a raised row and a pale left edge.

Use .sim-row buttons inside a .sim-panel--main. Mark the open item with aria-current="true". The consumer provides the source, time, title and a one-line summary. Use .sim-row__flag only for something that needs the owner, such as Needs your OK.

ModelRow

A row of data the model produced, so the owner can tell it apart from their own input.

Use .sim-model-row under a .sim-label--accent heading. The consumer provides a short type in a span, such as Task or Person, followed by the value. Don't use it for content the owner wrote.

TimelineBlock

One entry on the day's timeline, as an event, a fitted task or free time.

Use .sim-block for events, .sim-block--task for tasks the plan fitted, and .sim-block--free for free time. Put the title in b, metadata in small, and any model explanation in em, which renders in accent.

The consumer provides the time column and sets each block's height in proportion to its duration. Keep the minimum height at 68px, or 44px for free time.

Graph

GraphNode

A node in any graph, with a kind, a title and named ports.

Use .sim-node. Add .sim-node--tall for two port rows and .sim-node--accent for a node that calls the model or casts data. Add .sim-port--sink or .sim-port--source to name each port, .sim-port--row2 for the second row, and .sim-port--open for a source left unwired. Set aria-selected="true" on the selected node.

The consumer positions nodes and draws edges from port to port in arrow. Sinks sit on the left and sources on the right. Keep port names short and lowercase.
